      1. 01 2010–2012 · Northcentral Technical College

        Tech school

        An AAS in IT Network Specialist (Unified Communications), plus a technical certificate in website hardware and software administration. Graduated in December 2012.

      2. 02 2013 · Charter Communications, Madison

        Turning up circuits

        My first job in tech, on Charter's enterprise fiber team: point-to-point circuits, cell backhaul and large multipoint networks for business customers. I built each config by hand and tested every turn-up before calling it done, which is how I learned the network inside out.

      3. 03 ~2016 · The first tool

        A spreadsheet that did the typing

        My first program was a Visual Basic spreadsheet that filled in our order system: circuit IDs, IPs, VLANs, device assignments, even the Visio diagram. It was mostly if statements, the way first programs are, and before long the whole team was using it.

      4. 04 2016–2018 · The Time Warner merger

        One set of standards for a bigger network

        When Charter and Time Warner Cable merged, our all-Cisco region went multi-vendor, and the team needed standards everyone could share. I wrote our customer circuit standards for internet, voice and WAN in Confluence, ran the space as its admin, and built a JavaScript tool that generated Juniper MX configs to match. I was also sent to help with the network transition in the new region, and along the way I earned my CCNP, JNCIA, Nokia NRS I and MEF-CECP.

      5. 05 2020 on · Python and maintenance windows

        Audit first, then change it at night

        New router standards were landing every week, so I picked up Python and wrote audits that checked every router in the region against them. The audits found the gaps, and I closed them in overnight maintenance windows: a pre-check of every router, the potentially service-impacting changes, then a post-check of every router, each one reviewed to make sure we were in the clear. The before and after were saved for every router.

        Those changes touched almost every section of the config: BGP route policies, the IGP, QoS policies and network management, on production routers carrying business customers and cell-tower backhaul.

        When the regional QoS policy needed rewriting, I rewrote it and rolled it out to every PE router.

      6. 06 2020 on · Migrations

        Send me the cut sheet.

        Migrations meant hundreds of sites, each needing a method of procedure that took hours to write by hand. So the team sent me the cut sheet, and my script logged in to each device, pulled the config, picked out every variable that mattered, and wrote the procedure and the new config. Basically, press play.

      7. 07 2023–2026 · DevOps team

        A platform for the whole engineering org

        That automation work led to a spot on the DevOps team, building tools for network engineers. I was one of the lead developers on our network inventory and security platform: discovery crawled the network over SSH into a SQL inventory, and security modules rotated and audited passwords on everything it found, across hundreds of thousands of devices. I built the inventory database (MariaDB, later PostgreSQL) and the multi-vendor Paramiko modules, quirks and all, and we shipped through GitLab merge requests, code review and CI/CD.

      8. 08 2026 → now · The basement

        The home lab

        In early 2026 I started building a garden planner, mostly to see what AI coding could do. By spring there was a Mac Studio in my basement next to two Raspberry Pis, and the planner, GrowYear, is now live on the internet. The house got a voice, too. It escalated.

      Mac Studio

      Tests, builds and ships it, and rolls back if a health check fails

      The app
      React 18 and TypeScript, built with Vite: Tailwind, Radix UI (shadcn/ui), TanStack Query and Zustand. It's a static bundle that nginx serves.
      The back end
      Supabase, trimmed to the three parts it needs, in Docker: Postgres, GoTrue for sign-in and PostgREST for the API. About half a gigabyte of a 2 GB Pi.
      Sign-in and data
      Google sign-in only. Row-level security in Postgres decides every read and write: your garden is yours, and the seed catalog is read-only to everyone else.
      Where it runs
      My second Raspberry Pi, in the basement, at mygrowyear.com. A Cloudflare Tunnel carries the traffic, so nothing at home is open to the internet.
      Shipping it
      One command from the Mac Studio: typecheck, tests, build, database migrations, an atomic switch to the new release, then a health check that puts the old one back if anything fails.
      Keeping it
      Nightly database backups, copied to another machine in the house, and a monitor that checks its public address every two minutes.

      P.S. · How I made this

      Make one of your own.

      This page lives on a Raspberry Pi in my basement, and everything on it was made on hardware in my house. Here’s how I built it, step by step, so you can build yours.

      Human-directed, every line

      Every word on this page started with me: my stories, my notes and voice memos, and a lot of corrections. Claude Code did the typing and wrote the code; I decided what it says, read every change, and sent it back when it was wrong. Nothing here is an AI’s idea of me. It’s mine.

      2. 02

        I describe what I want; Claude Code writes the code and a first draft of the words. I read every change before it ships, and when something’s off (a claim that isn’t quite true, a section that drags), I say so and it goes around again. This page took dozens of rounds.

      3. 03

        Host it at home, with no open ports

        A Raspberry Pi 4 runs nginx, listening only on its own loopback address. My house sits behind Starlink’s carrier-grade NAT, so nothing on the internet can dial in. Instead, cloudflared on the Pi dials out to Cloudflare and keeps an encrypted tunnel open, and your request rides it home.

        # nginx on the Pi: loopback only, so the tunnel is the one way in
listen 127.0.0.1:8088;

# the tunnel's routing, set through Cloudflare's API
okay-cool.net    →  http://127.0.0.1:8088
anything else    →  404

        Your turn A Cloudflare account, a domain and cloudflared. No port forwarding, and your home IP address never shows up anywhere.
